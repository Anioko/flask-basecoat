Why Basecoat docs exist

Teams love the polish of shadcn/ui, but its starter defaults assume a Next.js workspace. Basecoat Docs bring the same navigation, layout, and interaction patterns to Flask so product squads can document UI decisions where the backend already lives.

Aligned with Basecoat UI

Components ship with Basecoat class names, giving you light/dark theming, spacing tokens, and state styles out of the box.

Optimized for cross-functional teams

Writers, designers, and engineers collaborate in the same repo: editorial updates happen in Jinja, while previews stay wired to live Tailwind utilities.

What you get today

  • Interactive shell mirroring ui.shadcn.com, including responsive sidebar, theme toggle, and contextual pagination.
  • Foundational guides covering installation, configuration, theming, and project conventions tailored for Flask deployments.
  • Block previews rewritten with Basecoat primitives and wired for copy-to-clipboard and forthcoming code tabs.
  • Registry scaffolding ready to import the entire shadcn/ui block catalogue as we expand coverage beyond the initial set.

How the documentation is structured

The docs blueprint keeps content declarative: each page is registered in app/docs/navigation.py with its slug, description, and template. Rendered pages combine prose, macros, and live previews so your team can ship design decisions and implementation details together.

When to use this blueprint

Reach for Basecoat Docs when you want shadcn/ui ergonomics without adopting a new frontend stack. Because everything renders server-side, you can document API contracts, business rules, and UI decisions right next to the routes that need them.

As the registry grows, your docs serve as the canonical reference: the same markup powers live previews, component snippets, and the UI your customers see.
