Docs blueprint at a glance

The documentation experience lives inside its own Flask blueprint so we can iterate on content, layout, and demos without touching the rest of the product. Think of it as a mini site with familiar shadcn/ui ergonomics layered on Basecoat primitives.

  • Self-contained routing. All requests flow through the docs blueprint.
  • Declarative navigation. Every page is registered in DOCS_NAV for ordering, metadata, and pagination.
  • Reusable shell. A single layout template renders the sidebar, top bar, search, table of contents, and pagination.
  • Live previews. Snippets and macros keep Basecoat markup alongside the prose that documents it.

Remember — Because the docs blueprint is independent, you can deploy content-only updates (copy tweaks, new blocks, accessibility notes) without redeploying your customer-facing blueprints.

Where everything lives

These are the core files that power the docs experience:

Path Role
app/docs/__init__.py Initializes the docs blueprint and exposes it for registration in create_app.
app/docs/routes.py Provides the /docs/<slug> route, resolves navigation metadata, and renders the requested page.
app/docs/navigation.py Holds the DOCS_NAV structure plus helpers for breadcrumbs, pagination, and sidebar rendering.
app/templates/docs/layout.html Shared shell that outputs the sidebar, search, top toolbar, page header, on-page TOC, and pagination links.
app/templates/docs/pages/* Content pages that extend the shell and provide prose, code, and component previews.
app/templates/docs/macros/* Reusable snippet macros for block previews and UI patterns.
app/static/styles/docs.css Layer of custom styling that replicates the shadcn/ui look-and-feel on top of Basecoat utilities.
app/static/scripts/docs.js Client-side enhancements: theme persistence, copy buttons, mobile nav, search, and sticky table of contents.

How requests resolve

Request pipeline

  1. Flask receives /docs/<slug> and hands it to the docs blueprint.
  2. find_page in navigation.py validates the slug and returns the full nav record.
  3. routes.py computes breadcrumbs, previous/next pointers, and pulls the template path from the nav record.
  4. The layout template receives page, breadcrumbs, prev_page, and next_page to render the chrome.

Breadcrumbs, search, and TOC

The layout uses the metadata provided by DOCS_NAV to populate breadcrumbs and the new top-bar search. On the client, docs.js scans each page for h2/h3 headings to build the sticky “On this page” navigation automatically.

Templates and macros

Layout shell

app/templates/docs/layout.html is the only template rendered directly by the route. It wraps your content with the sidebar, top bar, search overlay, sticky TOC, and pagination controls.

Page templates

Each page under app/templates/docs/pages extends the layout and provides prose, headings, and component embeds. Keep headings semantic so the on-page TOC renders useful anchors.

Snippet macros

Macros in app/templates/docs/macros (and supporting data in app/docs/snippets.py) let you reuse block previews across categories. As we expand Basecoat’s coverage of the shadcn registry, add new macros rather than duplicating markup between pages.

Static assets

CSS pipeline

app/assets/styles/input.css imports Tailwind, Basecoat, and any docs-only utilities. Running npm run build:css compiles everything into app/static/styles/app.css; docs.css overlays the shadcn-inspired treatment.

Docs JavaScript

docs.js ships minimal vanilla JS so the docs stay dependency-light: theme persistence via localStorage, mobile sidebar toggling, copy-to-clipboard buttons, search filtering, and the scroll-spy TOC.

Add a new page

  1. Create app/templates/docs/pages/<your-slug>.html and extend {% raw %}{% extends 'docs/layout.html' %}{% endraw %}.
  2. Add semantic headings (h2, h3) and include snippet macros or code blocks as needed.
  3. Register the page in DOCS_NAV with its title, slug, description, and template path.
  4. Restart Flask (or let the reloader handle it) and confirm the sidebar, search, TOC, and pagination pick up the new entry.

Style guide — Keep sidebar descriptions short (ideally under 90 characters). Clear summaries make the new search results easier to scan.
